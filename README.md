[![CodeFactor](https://codefactor.io/repository/github/jslachta/localenames/badge)](https://codefactor.io/repository/github/jslachta/localenames)

Names of languages, countries and currencies in almost any language, for .NET. Look a name up by its code, or a code by its name.

The data comes from [Unicode CLDR](https://github.com/unicode-org/cldr-json), is embedded in the package, and needs no network access or OS culture data. Targets `netstandard2.0`, `net8.0` and `net10.0`.

## Install

```
dotnet add package LocaleNames
```

`LocaleNames` is a meta package that references two others, which you can use on their own:

| Package | Contents |
| --- | --- |
| `LocaleNames.Core` | The code. Contains no data. |
| `LocaleNames.Data` | The CLDR data, embedded in an assembly. |
| `LocaleNames.Embed` | Build-time alternative to `LocaleNames.Data`, see below. |

### Embedding the data into your own assembly

Reference `LocaleNames.Embed` instead of `LocaleNames.Data` and the data is embedded into your assembly during the build, so no extra assembly is deployed. You can embed only the locales you need:

```xml
<PropertyGroup>
  <!-- Optional, everything is embedded when empty. Every locale is listed on its own: "en" does not include "en_GB". -->
  <LocaleNamesEmbedLocales>cs;en;en_GB</LocaleNamesEmbedLocales>
</PropertyGroup>
<ItemGroup>
  <PackageReference Include="LocaleNames.Embed" Version="..." />
</ItemGroup>
```

`LocaleNames.Core` finds the resources in loaded assemblies marked by the package. The mark is an assembly attribute generated by the SDK, so it is missing when `GenerateAssemblyInfo` is `false`. In that case, when you use `LocaleNames.Core` with `LocaleNames.Embed` (not the full `LocaleNames` or `LocaleNames.Data`), register the assembly yourself, once at startup, before the first lookup:

```csharp
LocaleResourceProvider.Register(typeof(SomeTypeInYourAssembly).Assembly);
```

With the full `LocaleNames` package no registration is needed, `LocaleNames.Data` is found on its own. A registered assembly is searched before it, so registering one there deliberately overrides the data in `LocaleNames.Data`.

## Usage

Get a translations object for the language you want the names in, then query it.

```csharp
var cs = LocaleTranslationsFactory.ForLanguageCode("cs-CZ");
var en = LocaleTranslationsFactory.ForCultureInfo(new CultureInfo("en-US"));
```

### Languages

```csharp
en.FindLanguageName("cs-CZ");   // Czech
en.FindLanguageCode("Czech");   // cs
en.GetAllLanguageCodes();
```

### Countries

```csharp
en.FindCountryName("DE");       // Germany
en.FindCountryCode("Germany");  // DE
en.GetAllCountryCodes();
```

### Currencies

```csharp
cs.FindCurrencyName("CZK");                      // česká koruna
cs.FindCurrencyName("CZK", PluralCategory.Few);  // české koruny
cs.FindCurrencyPluralNames("CZK");               // all plural forms
cs.FindCurrencyCode("česká koruna");             // CZK

en.FindCurrencySymbol("CZK");                       // CZK
en.FindCurrencySymbol("CZK", AltVariant.Narrow);    // Kč
en.GetAllCurrencyCodes();
```
